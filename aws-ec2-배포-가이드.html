시작 전에 — 무엇을 만들게 되나

완성되면 아래 구조가 됩니다. AWS의 작은 가상 서버 한 대가 화면(index.html)과 API를 함께 제공하고, 동료들은 브라우저로 주소 하나만 열면 됩니다.

[동료의 브라우저]
      │  ① http://탄력적IP 접속 → 화면이 뜸
      │  ② 기능 실행 시 접속 암호 1회 입력(브라우저에 저장됨)
      ▼
┌────────────────────────────────┐
│  EC2 가상 서버 (서울 리전)         │
│  · Ubuntu 24.04 / t3.micro     │
│  · FastAPI(server.py)가 항상 실행 │
│  · index.html도 이 서버가 제공    │
└────────────────────────────────┘
      │
      ▼  Gemini API (소진 시 DeepSeek 자동 전환)

준비물

  • 이메일 주소 1개 (AWS 계정용)
  • 해외 결제 가능한 신용카드 또는 체크카드 — 무료 플랜이어도 본인 확인용으로 등록이 필수입니다. 유료 전환 전까지는 청구되지 않고, 등록 시 확인용 가승인(1달러 수준)이 잠깐 잡혔다 풀릴 수 있습니다.
  • 휴대폰 (SMS 인증)
  • 맥 터미널 (파일 업로드와 서버 접속에 사용)

비용 요약

  • 신규 가입 시 크레딧 $100을 받고, EC2 실행·예산 생성 같은 활동을 하면 최대 $100을 더 받습니다. 크레딧은 가입 후 12개월간 유효합니다.
  • 이 구성의 사용량은 월 약 $12~14(서버 약 $9~10 + 공인 IPv4 약 $3.7 + 디스크 약 $1) 수준이고, 전부 크레딧에서 차감됩니다. 요금은 시점에 따라 조금 다르니 정확한 값은 콘솔의 요금 페이지에서 확인하세요.
  • 무료 플랜(Free plan)으로 가입하면 크레딧 범위를 넘는 카드 청구가 원천적으로 불가능합니다. 대신 가입 6개월 후(또는 크레딧 소진 시) 플랜이 만료됩니다 — 이때 할 일은 운영 섹션에 정리했습니다.
⚠️ 소요 시간 가입부터 접속 확인까지 여유 있게 약 1시간을 잡으세요. 부록 A(HTTPS)까지 하면 30분쯤 더 걸립니다. 중간에 끊어도 이어서 진행할 수 있습니다.
💡 표기 규칙 명령이나 설정에서 이런 색으로 표시된 부분은 본인의 값으로 바꿔 넣은 뒤 실행해야 합니다. 나머지는 그대로 복사해 붙여넣으면 됩니다(각 명령 상자의 복사 버튼 사용).

1단계AWS 계정 만들기

  1. aws.amazon.com/ko에 접속해 계정 생성(또는 AWS 계정 생성)을 누릅니다.
  2. 루트 사용자 이메일 주소와 계정 이름을 입력합니다. 이메일로 온 인증 코드를 입력하고, 루트 비밀번호를 만듭니다.
  3. 플랜 선택 화면이 나오면 무료(Free) 플랜을 선택합니다. 무료 플랜은 카드 청구가 아예 발생하지 않는 대신 최대 6개월까지 사용할 수 있습니다.
  4. 연락처 정보를 입력합니다. 계정 유형은 개인을 선택하고, 주소는 영문으로 입력하는 편이 무난합니다.
  5. 결제 정보(카드)를 등록합니다. 본인 확인 목적이며 무료 플랜에서는 청구되지 않습니다.
  6. 휴대폰 SMS 인증을 마치면 가입이 완료됩니다. 몇 분 뒤 계정이 활성화됩니다.
  7. console.aws.amazon.com에서 루트 사용자로 로그인합니다.
💡 한국어 콘솔 콘솔 화면 왼쪽 아래(또는 우상단 계정 메뉴)의 언어 설정에서 한국어를 선택할 수 있습니다. 이 가이드는 한국어 콘솔 기준으로 씁니다.
💡 여유가 될 때 한 가지 더 우상단 계정 메뉴 → 보안 자격 증명에서 루트 계정에 MFA(휴대폰 인증 앱)를 걸어두면 계정 탈취를 막을 수 있습니다. 지금 당장 필수는 아니니 배포를 마친 뒤에 해도 됩니다.

2단계서울 리전 선택

콘솔 우상단에 현재 리전(지역) 이름이 표시됩니다. 이를 눌러 아시아 태평양(서울) ap-northeast-2를 선택하세요.

⚠️ 중요 이후 모든 작업은 서울 리전에서 합니다. 나중에 "분명히 만들었는데 인스턴스가 안 보인다"면 십중팔구 다른 리전을 보고 있는 것입니다. 우상단 리전 표시부터 확인하세요.

3단계EC2 인스턴스(가상 서버) 만들기

  1. 콘솔 상단 검색창에 EC2를 입력해 EC2 서비스로 이동합니다.
  2. 주황색 인스턴스 시작 버튼을 누릅니다.
  3. 이름 및 태그 — 이름에 help-v2를 입력합니다.
  4. 애플리케이션 및 OS 이미지 — 빠른 시작에서 Ubuntu를 선택하고, 이미지가 Ubuntu Server 24.04 LTS, 아키텍처가 64비트(x86)인지 확인합니다.
  5. 인스턴스 유형 — t3.micro를 선택합니다(vCPU 2, 메모리 1GB — 이 도구에는 충분합니다).
  6. 키 페어(로그인) — 새 키 페어 생성을 누르고 다음처럼 만듭니다.
    • 이름 help-v2-key, 유형 RSA, 형식 .pem
    • 생성을 누르면 help-v2-key.pem 파일이 다운로드됩니다. 이 파일이 서버의 열쇠입니다. 다시 내려받을 수 없으니 지우지 말고 보관하세요(기본 위치는 ~/Downloads).
  7. 네트워크 설정 — 다음 두 개를 체크합니다.
    • ✅ SSH 트래픽 허용 — 위치는 위치 무관(0.0.0.0/0)을 선택합니다. 키 파일(.pem)이 있어야만 접속되므로 실질적 위험은 낮고, 집·학교 어디서든 관리할 수 있습니다.
    • ✅ 인터넷에서 HTTP 트래픽 허용 — 동료들이 접속하는 통로(포트 80)입니다.
  8. 스토리지 구성 — 기본값 8GiB(gp3) 그대로 둡니다.
  9. 오른쪽 요약에서 인스턴스 시작을 누릅니다. 1~2분 뒤 인스턴스 목록에서 상태가 실행 중이 되면 성공입니다.

4단계탄력적 IP — 고정 주소 붙이기

기본 공인 IP는 서버를 껐다 켜면 바뀝니다. 동료에게 알려줄 주소가 바뀌면 곤란하니 고정 IP(탄력적 IP)를 붙입니다.

  1. EC2 왼쪽 메뉴에서 네트워크 및 보안 → 탄력적 IP로 이동합니다.
  2. 탄력적 IP 주소 할당 → 기본값 그대로 할당.
  3. 방금 생긴 IP를 선택하고 작업 → 탄력적 IP 주소 연결 → 인스턴스에서 help-v2를 골라 연결합니다.

이제 이 IP가 서비스 주소입니다. 아래에서 계속 쓰니 적어두세요. 이 가이드에서는 탄력적IP라고 표시합니다(예: 3.35.123.45).

⚠️ 탄력적 IP 요금의 함정 인스턴스에 연결되어 있는 동안은 일반 공인 IPv4 요금(월 약 $3.7, 크레딧 차감)만 듭니다. 그런데 인스턴스를 지우고 IP만 남겨두면 미사용 IP 요금이 계속 나갑니다. 나중에 정리할 때는 부록 B 순서대로 IP까지 릴리스하세요.

5단계맥에서 서버 접속(SSH)

맥에서 터미널을 열고, 먼저 키 파일 권한을 조입니다(최초 1회만).

chmod 400 ~/Downloads/help-v2-key.pem

서버에 접속합니다.

ssh -i ~/Downloads/help-v2-key.pem ubuntu@탄력적IP
  • 처음 접속하면 Are you sure you want to continue connecting?이라고 묻습니다. yes를 입력하세요.
  • 프롬프트가 ubuntu@ip-…:~$로 바뀌면 서버 안에 들어온 것입니다.
💡 터미널 없이 접속하는 방법도 있습니다 EC2 콘솔에서 인스턴스를 선택하고 연결 → EC2 Instance Connect를 누르면 브라우저 안에서 서버 셸이 열립니다. 다만 파일 업로드(scp)는 맥 터미널이 필요하므로, 이 가이드는 터미널 기준으로 진행합니다.

6단계서버 기본 준비

서버 셸(방금 SSH로 들어간 화면)에서 실행합니다. 시스템을 최신화하고, 파이썬 가상환경 도구를 설치하고, 프로젝트 폴더를 만듭니다. 몇 분 걸릴 수 있습니다.

sudo apt update && sudo apt -y upgrade
sudo apt -y install python3-venv
mkdir -p ~/help_v2

중간에 보라색 재시작 안내 화면(Pending kernel upgrade 등)이 나오면 Enter로 넘어가면 됩니다.

7단계프로젝트 파일 올리기 + 접속 암호 정하기

7-1. 파일 업로드 (맥의 새 터미널 탭에서)

서버 셸은 그대로 두고, 맥에서 새 터미널 탭(⌘T)을 열어 실행합니다.

cd /Users/munhokang/82107/help_v2
scp -i ~/Downloads/help-v2-key.pem server.py index.html requirements.txt .env ubuntu@탄력적IP:~/help_v2/

4개 파일이 100%로 전송되면 성공입니다.

🚨 .env 파일 주의 .env에는 Gemini·NVIDIA 실제 API 키가 들어 있습니다. 이 파일은 지금처럼 scp로만 옮기고, 절대 카톡·메일·GitHub 등에 올리지 마세요.

7-2. 접속 암호(ACCESS_CODE) 정하기

동료에게 알려줄 접속 암호를 하나 정합니다(예: 학교 이름+숫자 조합). 서버 셸에서 실행하세요.

echo 'ACCESS_CODE=원하는암호' >> ~/help_v2/.env

확인은 이렇게 합니다. 마지막 줄에 방금 넣은 암호가 보이면 됩니다.

cat ~/help_v2/.env

이 암호가 설정되면 화면은 누구나 열 수 있지만, 생성 기능(API)은 암호를 입력한 사람만 쓸 수 있습니다. 선생님 컴퓨터의 로컬 개발 환경에는 ACCESS_CODE를 넣지 않았으므로 로컬에서는 암호 없이 그대로 동작합니다.

8단계파이썬 환경 만들기

서버 셸에서 가상환경을 만들고 의존성을 설치합니다.

cd ~/help_v2
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

설치가 끝나면 서버 코드가 정상적으로 읽히는지 확인합니다.

.venv/bin/python -c "import server" && echo OK

OK가 출력되면 다음 단계로 넘어갑니다.

9단계서버 상시 구동 등록(systemd)

SSH 창을 닫아도, 서버가 재부팅되어도 자동으로 실행되도록 시스템 서비스로 등록합니다. 서버 셸에서 아래 블록을 통째로 붙여넣으세요.

sudo tee /etc/systemd/system/help-v2.service > /dev/null <<'EOF'
[Unit]
Description=help_v2 (FastAPI - Gemini/DeepSeek proxy)
After=network.target

[Service]
User=ubuntu
WorkingDirectory=/home/ubuntu/help_v2
ExecStart=/home/ubuntu/help_v2/.venv/bin/uvicorn server:app --host 0.0.0.0 --port 80
AmbientCapabilities=CAP_NET_BIND_SERVICE
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF

포트 80은 원래 관리자 전용이라, AmbientCapabilities 줄이 이 서비스에만 80 포트 사용 권한을 줍니다.

서비스를 등록하고 시작합니다.

sudo systemctl daemon-reload
sudo systemctl enable --now help-v2
systemctl status help-v2 --no-pager

상태에 active (running)이 보이면 성공입니다. 실시간 로그는 다음 명령으로 볼 수 있고, Ctrl+C로 빠져나옵니다.

sudo journalctl -u help-v2 -f

10단계접속 확인, 동료에게 안내

  1. 브라우저 주소창에 http://탄력적IP를 입력합니다. 교무업무 지원 도구 화면이 뜨면 성공입니다.
  2. 아무 기능이나 실행해 봅니다. 처음 한 번 접속 암호를 물어보면 7-2에서 정한 암호를 입력하세요. 브라우저에 저장되어 다음부터는 묻지 않습니다.
  3. 생기부 작성 기능까지 실제로 한 번 돌려보고 결과가 나오는지 확인하세요.
⚠️ 반드시 http:// 로 접속 일부 브라우저는 주소를 자동으로 https://로 바꾸는데, 지금 구성은 HTTP 전용이라 https로는 열리지 않습니다. 안 열리면 주소창에 http://를 직접 붙여 다시 시도하세요. (https 적용 방법은 부록 A에 있습니다.)

동료에게 알려줄 것

  • 주소 http://탄력적IP — 즐겨찾기 등록을 권하세요.
  • 접속 암호 — 주소와 다른 채널(예: 직접 말로)로 전달하면 더 안전합니다.
  • 입력한 학생 관련 내용은 서버에 저장되지 않고 AI 호출에만 사용된다는 점.

운영 — 업데이트·요금·6개월 뒤 할 일

코드를 수정했을 때 반영하는 방법

맥에서 수정 → 파일 업로드 → 서비스 재시작, 세 단계입니다.

cd /Users/munhokang/82107/help_v2
scp -i ~/Downloads/help-v2-key.pem server.py index.html ubuntu@탄력적IP:~/help_v2/
ssh -i ~/Downloads/help-v2-key.pem ubuntu@탄력적IP "sudo systemctl restart help-v2"

참고로 이번 배포 준비 작업 이후, 로컬에서 쓸 때도 index.html 파일을 직접 열지 않고 .venv/bin/uvicorn server:app --port 8000으로 서버를 띄운 뒤 http://localhost:8000으로 접속하는 방식으로 바뀌었습니다.

요금·크레딧 확인

  • 콘솔 검색창에 Billing을 입력해 결제 및 비용 관리로 들어가면 이번 달 사용액과 크레딧 잔액·만료일을 볼 수 있습니다. 첫 달에 한 번 들어가서 크레딧이 잘 차감되는지 확인해 보세요.
  • 같은 곳의 예산(Budgets) → 예산 생성 → 제로 지출 예산 템플릿으로 알림을 만들어 두면, 크레딧 밖 실제 청구가 1원이라도 생길 때 이메일을 받습니다. 몇 번의 클릭이면 되고, 이런 활동이 추가 크레딧 적립 대상이 되기도 합니다.

6개월 뒤(또는 크레딧 소진 시) — 중요

🚨 무료 플랜 만료를 그냥 두면 서버가 사라집니다 무료 플랜은 가입 6개월 후 또는 크레딧 소진 시 만료됩니다. 만료되면 계정이 닫히고 서버가 중지되며, 90일 안에 유료 플랜으로 전환하지 않으면 데이터까지 영구 삭제됩니다. AWS가 만료 전에 이메일로 안내하니 가입 이메일을 꼭 챙겨 보시고, 달력에 가입 5개월째 알림을 하나 걸어두세요.

계속 운영하려면 만료 전에 콘솔 안내에 따라 유료 플랜으로 전환하면 됩니다(남은 크레딧은 유지, 소진 후부터 카드 청구 시작 — 이 구성 기준 월 약 $12~14, 약 2만 원). 그 시점에 비용을 줄이고 싶다면 월 $5 고정의 Lightsail로 옮기는 방법도 있습니다 — 그때 다시 도움을 요청하세요.

서버 중지·재시작

  • 인스턴스를 중지하면 동료들이 접속할 수 없습니다. 상시 서비스라면 계속 켜두는 것이 전제입니다.
  • 재부팅(콘솔 → 인스턴스 → 재부팅)해도 systemd 등록 덕분에 서비스가 자동으로 다시 뜨고, 탄력적 IP라 주소도 그대로입니다.

문제 해결

증상확인 순서
브라우저에서 페이지가 안 열림 ① 주소가 http://인지(https 아님) ② EC2 콘솔에서 인스턴스가 실행 중인지 ③ 보안 그룹 인바운드에 HTTP(80)가 있는지 ④ 서버 셸에서 systemctl status help-v2가 active인지 ⑤ sudo journalctl -u help-v2 -n 50으로 오류 로그 확인
암호를 넣어도 계속 "올바르지 않습니다" 서버 셸에서 cat ~/help_v2/.env로 ACCESS_CODE 값 확인(앞뒤 공백·오타 주의). 값을 고쳤다면 sudo systemctl restart help-v2 후 다시 시도 — 화면에서 틀린 암호는 다시 물어보므로 새로고침 없이 재입력하면 됩니다.
SSH/scp가 안 됨 ① 키 경로가 맞는지(~/Downloads/help-v2-key.pem) ② chmod 400을 했는지 ③ 사용자명이 ubuntu인지 ④ IP가 탄력적 IP가 맞는지
생성 기능에서 "사용량이 소진되었습니다(429)" 오류 Gemini 무료 사용량이 그날 한도까지 쓰인 것입니다. 시간이 지나면 회복되고, DeepSeek 예비 모델이 있는 기능은 자동 전환됩니다. 키를 늘리려면 로컬 .env의 GEMINI_API_KEYS에 키를 추가하고 위의 "코드 반영 방법"대로 .env를 다시 올린 뒤 재시작하세요.
코드를 올렸는데 반영이 안 됨 scp 후 sudo systemctl restart help-v2를 했는지 확인하세요. 브라우저 새로고침(⌘⇧R 강력 새로고침)도 필요할 수 있습니다.
인스턴스 목록이 비어 있음 우상단 리전이 서울인지 확인하세요.

부록 A. HTTPS 적용 — 무료 주소로 암호화 (강력 권장)

지금 구성(HTTP)은 통신이 암호화되지 않습니다. 이 도구에는 학생 관련 내용(생기부 초안 등)이 오가므로, 여유가 되는 대로 HTTPS를 적용하시길 강하게 권합니다. 도메인을 구매하지 않아도 무료 서브도메인(DuckDNS)과 무료 인증서(Caddy가 자동 발급)로 가능합니다. 약 20~30분 걸립니다.

A-1. DuckDNS 무료 주소 만들기

  1. duckdns.org에 접속해 구글 계정 등으로 로그인합니다.
  2. domains 칸에 원하는 이름(예: help82107)을 입력하고 add domain을 누릅니다.
  3. 생긴 도메인의 current ip 칸에 탄력적IP를 입력하고 update ip를 누릅니다.

이제 내이름.duckdns.org가 서버를 가리킵니다. IP가 고정이므로 갱신 프로그램은 필요 없습니다.

A-2. 보안 그룹에 HTTPS(443) 열기

  1. EC2 콘솔 → 인스턴스 선택 → 보안 탭 → 보안 그룹 클릭 → 인바운드 규칙 편집.
  2. 규칙 추가 — 유형 HTTPS, 소스 위치 무관(0.0.0.0/0) → 저장.

A-3. Caddy 설치 (서버 셸)

Caddy는 인증서 발급·갱신을 전부 자동으로 해주는 웹서버입니다. 아래는 우분투 공식 설치 절차입니다(최신 명령은 공식 문서 참고).

sudo apt -y install debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt -y install caddy

A-4. 우리 서버를 내부 포트로 옮기기

80 포트를 Caddy에게 넘겨야 하므로, FastAPI는 내부 전용(127.0.0.1:8000)으로 바꿉니다. 서비스 파일을 아래 내용으로 통째로 덮어씁니다.

sudo tee /etc/systemd/system/help-v2.service > /dev/null <<'EOF'
[Unit]
Description=help_v2 (FastAPI - Gemini/DeepSeek proxy)
After=network.target

[Service]
User=ubuntu
WorkingDirectory=/home/ubuntu/help_v2
ExecStart=/home/ubuntu/help_v2/.venv/bin/uvicorn server:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl restart help-v2

A-5. Caddy 설정

⚠️ 붙여넣기 전에 바꾸세요 아래 블록은 붙여넣는 즉시 실행됩니다. 복사한 뒤 메모장 등에서 색으로 표시된 세 곳(내이름 두 곳, 탄력적IP 한 곳)을 먼저 본인 값으로 바꾸고 나서 터미널에 붙여넣으세요.
sudo tee /etc/caddy/Caddyfile > /dev/null <<'EOF'
내이름.duckdns.org {
    reverse_proxy 127.0.0.1:8000
}

http://탄력적IP {
    redir https://내이름.duckdns.org{uri}
}
EOF
sudo systemctl restart caddy

두 번째 블록은 기존 IP 주소로 들어온 동료를 새 주소로 자동 안내하는 역할입니다.

A-6. 확인

  1. 브라우저에서 https://내이름.duckdns.org 접속. 첫 접속은 인증서 발급 때문에 몇십 초 걸릴 수 있습니다.
  2. 주소창에 자물쇠가 보이고 화면이 뜨면 완료입니다. 동료들에게 새 주소를 안내하세요.
  3. 안 되면 sudo journalctl -u caddy -n 50으로 로그를 확인하세요. 대부분 DuckDNS의 IP 오타이거나 443 포트 미개방입니다.

부록 B. 전부 지우는 방법

더 이상 운영하지 않기로 했다면 요금이 나올 수 있는 것부터 순서대로 지웁니다.

  1. EC2 → 인스턴스 선택 → 인스턴스 상태 → 인스턴스 종료(삭제). 디스크(EBS)는 기본 설정상 함께 삭제됩니다.
  2. 네트워크 및 보안 → 탄력적 IP → 해당 IP 선택 → 작업 → 연결 해제(이미 해제됐다면 생략) → 작업 → 탄력적 IP 주소 릴리스. 이걸 빼먹으면 미사용 IP 요금이 계속 나갑니다.
  3. 키 페어·보안 그룹은 요금이 없지만, 정리하려면 각 메뉴에서 삭제하면 됩니다.
  4. 마지막으로 결제 및 비용 관리에서 다음 달 청구 예정액이 0인지 확인하세요.
